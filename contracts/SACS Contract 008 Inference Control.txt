1. Purpose

This contract defines the canonical Inference Control layer of SACS.

It establishes the deterministic lifecycle by which SACS translates one Committed Control Command into one runtime-specific Inference Command Set without altering the command’s supervisory meaning, authority, restrictions, scope, ordering requirements, or bounded behavior.

Inference Control is the architectural boundary between canonical supervisory control and runtime-specific command representation.

It receives an already-authorized supervisory correction from Contract 007.

It determines how that exact correction is represented for one declared runtime under one committed translation context.

It does not determine whether the correction should exist.

It does not determine whether the correction was mathematically correct.

It does not determine whether the runtime should execute the translated instructions.

It does not determine whether execution succeeded.

Inference Control SHALL preserve both the positive requirements and the restrictive semantics of the Committed Control Command.

Preserved semantics SHALL include, where applicable:

* required actions;
* prohibited actions;
* parameter bounds;
* command scope;
* target scope;
* temporal scope;
* expiry;
* cardinality;
* ordering;
* partial-order constraints;
* atomicity requirements;
* transaction boundaries;
* failure conditions;
* compensation requirements;
* mandatory restrictions;
* authority limits;
* numeric tolerances;
* declared serialization semantics.

Inference Control SHALL NOT reinterpret supervisory intent.

Inference Control SHALL NOT recompute controller output.

Inference Control SHALL NOT re-evaluate objective or profile selection.

Inference Control SHALL NOT silently broaden supervisory authority.

Inference Control SHALL NOT remove mandatory restrictions.

Inference Control SHALL NOT substitute an approximate action for an unsupported action.

Inference Control SHALL NOT execute the translated result.

Its defining identity is:

Contract 008 deterministically transforms one Committed Control Command into one semantically and authoritatively equivalent runtime-specific Inference Command Set using only committed translation artifacts, without reconsidering the supervisory decision, expanding authority, removing mandatory restrictions, or assuming execution authority.

⸻

1.1 Translation Authority

Contract 008 owns semantic-preserving translation.

A conforming implementation MAY realize translation through:

* compilation;
* lowering;
* mapping;
* encoding;
* command construction;
* deterministic decomposition;
* deterministic parameter conversion;
* registered instruction selection;
* another explicitly registered translation mechanism.

Implementation technique does not alter Contract 008 authority.

Regardless of mechanism, the translated artifact SHALL satisfy the same semantic-preservation, authority-preservation, restriction-preservation, determinism, and commitment requirements.

⸻

1.2 Translation Equivalence

Two command representations are translation-equivalent when the resulting Inference Command Set:

1. preserves the intended supervisory effect of the Committed Control Command;
2. introduces no authority absent from the Committed Control Command;
3. removes no mandatory obligation, restriction, bound, or prohibition;
4. preserves the command’s target and scope;
5. preserves required ordering and atomicity semantics;
6. remains within the declared runtime capability and action model;
7. remains within the committed translation and numeric profiles;
8. is produced through an explicitly registered translation definition;
9. can be deterministically replayed from the same committed inputs;
10. is valid for submission to Contract 009 without requiring Contract 009 to reinterpret supervisory meaning.

Translation equivalence does not require structural identity.

One Control Command MAY translate into:

* one Inference Command;
* multiple totally ordered Inference Commands;
* multiple partially ordered Inference Commands;
* one atomic command bundle;
* one transactional command sequence;
* one runtime-native command carrying several bound parameters.

Structural decomposition is permitted only when the resulting set remains translation-equivalent.

⸻

1.4 Success and Failure Outcomes

A Contract 008 evaluation SHALL produce exactly one of:

Committed Translation Transaction

or:

Inference Translation Failure

A Committed Inference Command Set is an intermediate committed semantic translation artifact. It is not the terminal Contract 008 output or the Contract 009 handoff artifact.

A proposed or partially constructed Inference Command Set is not canonical.

An unsuccessful translation SHALL NOT expose an executable partial command set.

An unsupported or incompatible command SHALL NOT be approximated.

A translation failure is the correct outcome whenever registered translation equivalence cannot be established.

The key words MUST, MUST NOT, REQUIRED, SHALL, SHALL NOT, SHOULD, SHOULD NOT, RECOMMENDED, MAY, and OPTIONAL are normative conformance terms.

A requirement marked MUST, MUST NOT, SHALL, or SHALL NOT is binding on every conforming implementation within the applicable capability profile.

3. Architectural Identity

Inference Control is the SACS authority responsible for changing command representation without changing supervisory meaning.

Its defining architectural question is:

How must this already-canonical supervisory command be represented for this exact declared runtime?

Inference Control does not ask:

Should this command have been produced?

That question was resolved by Contract 007.

Inference Control does not ask:

Should the runtime execute these instructions?

That question belongs to Contract 009.

The constitutional boundary is:

        ↓
Contract 008
Committed Inference Command Set
                ->
Constructed Translation Transaction
                ->
Committed Translation Transaction
                ->
Execution Interface Handoff Envelope
        ↓
Contract 009
Execution Evaluation, Disposition, Submission, and Receipt

3.1 Inference Control Is a Translation Layer

Inference Control is:

* deterministic;
* cycle-bound;
* capability-constrained;
* configuration-bound;
* registry-bound;
* semantics-preserving;
* authority-monotonic;
* restriction-preserving;
* implementation-specific at its output boundary;
* execution-neutral.

Inference Control is not:

* a Controller;
* a Governance evaluator;
* an Objective evaluator;
* an Operational Profile selector;
* a Reference State builder;
* a runtime router;
* a provider selector;
* an optimizer;
* a scheduler;
* a retry manager;
* a transport layer;
* an execution gate;
* an execution adapter;
* a receipt processor;
* a task-content generator;
* a verification authority.

⸻

3.2 Representation Versus Decision

The Committed Control Command and the resulting Inference Command Set are different artifact classes.

The Committed Control Command expresses canonical supervisory correction.

The Inference Command Set expresses the exact runtime instructions that represent that correction for one declared runtime.

For example:

Committed Control Command:
Reduce update gain to 0.35 within the authorized target scope.
Committed Runtime Capability Profile:
The target runtime supports direct update-gain restriction.
Committed Translation Configuration:
Map canonical update_gain_limit to runtime field delta_gain_limit.
Inference Command:
Set delta_gain_limit = 0.35 for the declared target scope.

The field name changes.

The representation changes.

The supervisory meaning does not change.

The target scope does not change.

The authority does not expand.

The restriction does not weaken.

⸻

3.3 Capability Awareness

Inference Control MAY determine:

* whether the declared runtime can faithfully represent the command;
* whether a registered equivalent translation exists;
* whether the command may be validly decomposed;
* whether the required parameter domain is representable;
* whether ordering requirements can be represented;
* whether atomicity requirements can be represented;
* whether required failure semantics can be represented;
* whether all mandatory restrictions can be preserved.

Inference Control SHALL NOT determine:

* whether another runtime should be selected;
* whether another model should be selected;
* whether a weaker action is preferable;
* whether a less restrictive action is sufficient;
* whether a different Control Command would be easier to execute;
* whether provider cost justifies semantic alteration;
* whether latency justifies semantic alteration;
* whether implementation convenience justifies semantic alteration;
* whether unsupported restrictions may be omitted;
* whether an approximate replacement should be generated.

Capability awareness answers:

Can this runtime faithfully represent the committed command?

It does not answer:

What different action should be used if it cannot?

⸻

3.4 Translation Difficulty Does Not Create Authority

Translation difficulty, provider preference, runtime inconvenience, cost, latency, implementation limitation, unavailable optimization, or adapter simplicity SHALL NOT permit Inference Control to:

* reinterpret supervisory intent;
* weaken a restriction;
* broaden a parameter;
* narrow a mandatory effect without authorization;
* replace the target;
* change the runtime;
* omit an instruction;
* add an instruction;
* alter ordering;
* alter atomicity;
* substitute a different supervisory action.

When faithful translation is unavailable, Contract 008 SHALL fail.

⸻

3.5 Fundamental Architectural Invariant

The fundamental invariant of Contract 008 is:

Inference Control changes representation only. It SHALL preserve supervisory meaning, mandatory restrictions, scope, ordering, atomicity, numeric obligations, and authority while producing a runtime-specific command representation.

This invariant governs every translation definition, compatibility evaluation, binding, normalization, validation, certification, commitment, replay, and handoff defined by this contract.

4.3 Translation Authority Versus Execution Authority

Contract 008 defines what runtime instructions faithfully represent the Committed Control Command.

Contract 009 determines whether and how those instructions may enter execution.

Contract 008 MAY define required:

* command order;
* partial order;
* atomicity;
* transaction grouping;
* all-or-none semantics;
* compensation semantics;
* expiry;
* preconditions;
* target binding.

Contract 009 SHALL enforce, reject, defer, or otherwise disposition those requirements according to its own authority.

Contract 008 SHALL NOT:

* dispatch instructions;
* reserve runtime resources;
* test live destination availability as execution authority;
* retry failed execution;
* reorder instructions for operational convenience;
* split an atomic bundle;
* merge independent bundles;
* treat acknowledgement as execution success;
* construct execution receipts.

The terminal artifact of Contract 008 is a canonical Inference Command Set.

It is not an Execution Package.

⸻

4.4 Semantics-Preserving Parameter Normalization

Contract 008 MAY normalize runtime parameters only when semantic identity is preserved.

Permitted normalization MAY include:

* exact unit conversion;
* exact scale conversion;
* registered enum encoding;
* canonical field-name mapping;
* deterministic serialization conversion;
* deterministic precision conversion within a committed tolerance;
* explicit representation of absent optional values;
* canonical ordering of semantically unordered fields;
* registered expansion of one canonical parameter into several coupled runtime parameters.

Normalization SHALL NOT include:

* clipping to runtime limits;
* silently replacing unsupported values;
* rounding beyond authorized tolerance;
* widening a bound;
* narrowing a required effect;
* changing target scope;
* changing temporal scope;
* changing cardinality;
* changing parameter interaction;
* inserting runtime defaults that alter meaning;
* omitting unsupported restrictions;
* resolving ambiguity through provider convention;
* coercing incompatible units;
* converting failure into a weaker command.

Any transformation that changes supervisory meaning is not normalization.

It is an unauthorized substitution.

⸻

4.5 Translation Configuration Authority

The Translation Configuration SHALL be selected and committed outside the translation evaluation itself by an authorized operational, deployment, or configuration authority.

Contract 008 MAY:

* consume the committed Translation Configuration;
* verify its integrity;
* bind its referenced definitions;
* validate its applicability;
* apply its approved translation rules.

Contract 008 SHALL NOT:

* select among translation strategies based on runtime preference;
* search for an easier Translation Configuration;
* synthesize a missing Translation Configuration;
* mutate the committed Translation Configuration;
* substitute a different Translation Configuration after incompatibility;
* resolve an unspecified strategy using implementation defaults.

A Translation Configuration authorizes representation rules.

It does not authorize a new supervisory action.

⸻

4.6 Authority Monotonicity

Contract 008 SHALL be authority-monotonic.

Successful translation SHALL not produce more authority than the Committed Control Command.

Failed translation SHALL produce no executable Inference Command Set.

Fallback translation SHALL be permitted only when the fallback representation:

1. was selected or authorized by the committed Translation Configuration;
2. is explicitly registered as translation-equivalent;
3. preserves every mandatory restriction and obligation;
4. passes the same equivalence and authority-preservation validation;
5. does not select a new runtime, target, or supervisory action.

A merely safer, weaker, cheaper, faster, or more available command is not automatically translation-equivalent.

5. Canonical Inputs and Translation Context

Contract 008 distinguishes between:

1. the sole canonical supervisory decision input;
2. required committed translation-context artifacts;
3. referential authority context;
4. immutable reusable definitions;
5. prohibited inputs.

These categories SHALL NOT be conflated.

⸻

5.1 Sole Canonical Supervisory Decision Input

Contract 008 SHALL consume exactly one Committed Control Command as its sole supervisory decision input.

The Committed Control Command SHALL:

* be produced by Contract 007;
* be identified by one valid Controller Commitment Record;
* belong to the same supervisory cycle as the translation evaluation;
* be immutable;
* include or reference its canonical schema version;
* include or reference its command type;
* include or reference its target scope;
* include or reference its authority bounds;
* include or reference its mandatory restrictions;
* include or reference its ordering and atomicity requirements;
* include or reference its Numeric Profile;
* include or reference its Action Space Definition;
* include or reference its Authority Certificate;
* include or reference its controller commitment lineage;
* include a valid artifact hash.

Contract 008 SHALL NOT treat any other artifact as supervisory command authority.

The Committed Control Command answers:

What supervisory correction is canonical?

No translation-context artifact may answer that question again.

⸻

5.4 Governance Snapshot Consumption

The preferred Core model is that Contract 008 does not directly consume the full Governance Snapshot.

Contract 008 SHOULD instead consume:

* the Authority Certificate;
* the Control Constraint Set reference;
* the Action Space Definition reference;
* the committed Governance Snapshot identifier;
* the exact governance-derived restrictions already bound into the Committed Control Command.

Contract 008 MAY consume the committed Governance Snapshot only when:

1. a registered Translation Definition requires one explicitly identified governance field;
2. that field was not reducible into the Committed Control Command or Authority Certificate;
3. the Translation Configuration authorizes that exact reference;
4. the exact Governance Snapshot is cycle-bound and immutable;
5. the field is used solely to preserve the existing command;
6. the translation does not reconsider command authorization;
7. the consumption is recorded in lineage.

Direct Governance consumption SHALL NOT permit Contract 008 to produce a different supervisory decision.

Governance may constrain representation.

It may not be reinterpreted to rewrite the command.

5.7 Input Coherence Requirements

Before translation binding begins, Contract 008 SHALL verify that:

* exactly one Committed Control Command is present;
* the command is identified by one valid Controller Commitment Record;
* the command and Controller Commitment Record belong to the same cycle;
* the Runtime Capability Profile applies to the declared runtime target;
* the Translation Configuration applies to the command type and runtime target;
* the Translation Numeric Profile is compatible with the command’s Numeric Profile;
* all required registry snapshots are present;
* every referenced definition resolves by exact identifier, version, and hash;
* all authority references resolve to the same upstream commitment lineage;
* no required artifact is mutable;
* no required artifact is stale under its declared validity rules;
* no required artifact belongs to a different supervisory cycle unless explicitly declared reusable;
* no incompatible registry versions are combined;
* no command restriction is missing from the translation context;
* no target ambiguity exists;
* no translation strategy remains unspecified.

Failure of input coherence SHALL prevent translation evaluation.

5.8 Constitutional Non-Substitution Invariant

Contract 008 SHALL consume exactly one Committed Control Command as its sole supervisory decision input.

It MAY additionally consume only the committed capability, translation, numeric, authority-reference, and registry artifacts required to represent that command for one declared runtime.

Inference Control SHALL NOT:

* revisit controller mathematics;
* reconsider supervisory intent;
* re-evaluate objective selection;
* re-evaluate profile selection;
* reauthorize the Control Command;
* select a different Control Command;
* select a different runtime;
* select a different target;
* expand authority;
* remove mandatory restrictions;
* relax command bounds;
* replace unsupported values;
* substitute an approximate supervisory action;
* omit unsupported command requirements;
* use provider defaults to resolve missing semantics;
* generate a best-effort executable command.

When exact registered translation equivalence cannot be established, Contract 008 SHALL produce one explicit Inference Translation Failure and no canonical Inference Command Set.
